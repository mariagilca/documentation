Before you begin setting up OpenLM Platform, verify that you meet the following requirements.

| Requirement | Details | How to verify |
|---|---|---|
| **OpenLM Platform account** | An active, registered OpenLM Platform account. | If you do not have one, you will create it in the next step. |
| **On-premises servers** | Physical or virtual servers to run OpenLM Broker and the Directory Synchronization Agent (DSA). | The Broker runs on Windows (Server 2012+, 8.1, 10) or Linux (Ubuntu, CentOS). The DSA runs on Windows only. |
| **End-user workstations** | Workstations where the Workstation Agent collects activity data. | The Workstation Agent supports Windows 10/11, Ubuntu 18/20, and CentOS 8. |
| **Internet access** | Reliable internet from on-premises machines to the OpenLM Platform. | Verify that firewalls and proxies allow outbound HTTPS (port 443) traffic. |
| **Network access to license servers** | The Broker machine must reach your license manager servers over the network. | Confirm you can connect to your license server ports (for example, port 27000 for FlexNet). |
| **Directory access** | The DSA machine must reach your directory source — a local LDAP/Active Directory server or a cloud directory such as Microsoft Entra ID. | Confirm network or internet access from the DSA machine to your directory. |
| **License manager knowledge** | Know what license managers you use (for example, FlexNet, Sentinel RMS, IBM LUM) and how they are configured. | Identify each license manager type, server hostname, and port number. |
| **Network and security readiness** | Familiarity with firewall rules and secure communication practices. | Review your organization's policies for allowing new outbound connections. |

For detailed hardware and OS specifications per component, see [Components system requirements](/cloud/deployment-operations/system-requirements).
