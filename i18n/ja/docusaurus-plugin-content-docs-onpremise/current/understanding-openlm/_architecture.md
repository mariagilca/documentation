# OpenLMプラットフォームアーキテクチャ

OpenLM Annapurnaは、ワークステーションエージェントとブローカーを介してアプリケーションと実行可能ファイルのデータを収集します。これらのコンポーネントは、組織の完全修飾ドメイン名（FQDN）またはDNS名を表すOpenLMゲートウェイに接続します。ゲートウェイはデータをOpenLMサービスに転送し、サービスはそれを適切なデータベースに保存します。

## 主要コンポーネント

- **ワークステーションエージェント**: 個々のユーザーマシンからデータを収集します。
- **ブローカー**: ライセンスマネージャーサーバーで実行されます。ライセンス使用状況データを収集し、関連するサービスに送信します。
- **OpenLMゲートウェイ**: エントリポイントとして機能し、個々のサービスにデータをルーティングします。
- **OpenLMサービス**: 収集されたデータを処理、エンリッチ、管理します。
- **データベース**: サーバーデータベース、IDサービスデータベース、DSSデータベース、レポートデータベースなど、専用システムに処理済みデータを保存します。

## マイクロサービスとKubernetes

OpenLM Annapurnaは、Kubernetesクラスターに展開されたマイクロサービス上で実行されます。
各サービスは、Kubernetesノード上のポッド内のコンテナ内で実行されます。
サービスは内部データベースにデータを保存し、非同期処理のためにKafkaをメッセージキューとして使用します。

## アーキテクチャレベル

![OpenLM Annapurnaの高レベルアーキテクチャ](/img/on_premise/understanding_openlm/high-level.png)

### レベル1：高レベルのデータフロー

- ワークステーションエージェント、ブローカー、およびその他のサービスは、独自のデータベースにデータを書き込みます。
- サービスはKafkaトピックにデータを公開します。
- レポートサービスはKafkaデータを集約します。
- レポートサービスはレポートデータベースにデータを保存します。
- レポートダッシュボードはレポートデータベースからデータを読み取ります。

![Open-LM Annapurnaレベル1アーキテクチャ](/img/on_premise/understanding_openlm/level-1.png)

### レベル2：詳細なデータパイプライン

- ワークステーションエージェントとブローカーは、PCとサーバーからデータを収集します。
- エージェントハブとブローカーハブは、このデータを統合します。
- エージェントハブとブローカーハブからのデータは、MongoDBとKafkaに保存されます。
- 他のサービス（ユーザー、プロジェクト、サーバー）は、関連するKafkaトピックを消費します。
- エンリッチメントサービスは、すべてのサービスからのデータをマージおよび拡張し、Kafkaに再度公開します。
- Apache Sparkは、レポート用にエンリッチされたKafkaデータを集約します。
- Sparkは結果をレポートデータベースに書き込みます。
- ビジネスインテリジェンスツールは、レポートデータベースにアクセスします。

![OpenLM Annapurnaレベル2アーキテクチャ](/img/on_premise/understanding_openlm/level-2.png)

## エンリッチメントサービス

Annapurnaには、収集されたデータを統合および拡張するためのエンリッチメントサービスが含まれています。

- **割り当てエンリッチメントサービス**: 割り当てIDを使用して割り当てデータを追加します。
- **使用状況エンリッチメントサービス**: セッションIDを使用して使用状況データを拡張します。
- **拒否エンリッチメントサービス**: 拒否IDを使用して拒否データを処理します。

## データストレージとリカバリ

Annapurnaは、損失または破損の場合のデータリカバリをサポートするために、ステージングデータベースを使用します。
このステージングデータは、後で内部リカバリソースとして機能するMongoDBに移動されます。
