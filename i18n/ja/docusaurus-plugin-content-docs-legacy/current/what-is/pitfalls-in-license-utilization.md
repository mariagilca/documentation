## ライセンス使用における落とし穴とは?

この記事では、厄介なライセンス問題について説明します。クライアントが望むものを手に入れられないだけでなく、必要なものさえ手に入れられないいくつかのシナリオを提示します。

ソフトウェアベンダーと新しいライセンスを交渉する際に、紆余曲折を知り、認識しておくことにはメリットがあります。また、ネットワーク上の実際のライセンス使用状況を監視することのメリットも強調しています。

## 保持されているライセンス

私が言及している最初のシナリオは、「保持されている」ライセンスです。この用語は、支払い済みで、現在使用されておらず、それにもかかわらずエンドユーザーが利用できないネットワークライセンスを表します。アプリケーションを閉じた後でも、ライセンスは単に利用できないままになります。

保持されているライセンスの本来の目的は、アクティブなユーザーがアプリケーションをシャットダウンした後にライセンスを再要求できる猶予期間を設けることでした。個人的には、この利点はいくつかの理由で乱用されていると感じています。

1. 使えないものにお金を払うべきではありません。以上です。
2. 最小保持時間の設定は、発行元に予約されています。お客様は、この期間をキャンセルまたは短縮することはできません。
3. 保持期間の構成は、発行元の裁量に委ねられています。彼らは好きなだけ長く設定できます。お客様は、この件に関して発言権がありません。
4. 保持時間の割合は、明示的に報告されません。この情報は、OpenLMなどのライセンス監視ツールによって明示的に抽出する必要があります。

「保持されている」ライセンスは、この目的のために専用のメカニズムを採用しているさまざまなライセンスマネージャーによる一般的な慣行です。

- Sentinel RMSでは、「保持されているライセンス」という用語が使用されます。ライセンスは、ライセンス使用状況レポートで「保持」可能として記載されています。例：

**|- 保持されているライセンス：許可、保持時間はライセンスによって設定されます。**

**|- 保持時間：30分**

アプリケーションをシャットダウンすると、ライセンスのステータスは次のようになります。

**|- ステータス：2015年8月4日木曜日10:48:07から実行中...**

**|- ステータス：このライセンスは保持されています。**

- FlexLMでは、ライセンスの保持は「リンガータイム」メカニズムを介して実装されます。お客様は、オプションファイルを介してリンガーを適用することを選択でき、これにより、前述の猶予期間が得られます。ただし、ソフトウェア発行元は、独自の最小リンガータイム値を設定できます。その場合、より長い期間が適用され、アプリケーションがシャットダウンされ、より長い期間が経過するまでライセンスは解放されません。

## ライセンスの保持について何ができますか?

ライセンスを購入した後では、おそらくあまり何もできません。しかし、お客様は交渉の席でこの落とし穴に注意し、自分のお金で実際に何を得ているのかを知り、OpenLMなどのライセンス監視ツールでアイドル時間の割合を監視できる必要があります。

## オープンチェックポリシー

もう1つの不快な落とし穴は、社内で「オープンチェック」ライセンスポリシーと呼んでいるものです。このタイプのライセンス管理スキームは、事前定義された使用制限内で「従量課金制」ライセンスを採用しています。この制限は交渉の席で合意され、お客様のソフトウェアに対する計算された支出を反映しています。使用量ごとに支払うこととは別に、このライセンススキームのもう1つの魅力的な利点は、所有コストがないことです。

問題は、ライセンスマネージャーがライセンスの使用を合意された制限に制限しない場合に発生します。また、今後の使用制限や、それを超えたことに対する警告に失敗する場合もあります。これにより、エンドユーザーは自由にライセンスを付与され、合意された制限を超える可能性があるため、支出の管理が失われます。

使用制限を超えると、高額な支払い要求が発生することに注意してください。このような予期せぬ計算外の費用は、特に中小企業にとって痛手となります。このようなライセンススキームの例は、次のとおりです。

### Bentley

[BentleyはCADソフトウェアハウスであり、](https://www.google.com/url?q=https://www.openlm.com/monitoring-bentley-select-license-manager/&sa=D&usg=AFQjCNEBTEIPbAymlrUuOI898vvRzYhWuQ)建築、GIS、プラントインフラ、土木工学プロジェクト向けの市場をリードするソリューションを製造しています。Bentleyのライセンス管理モデルは、[「トラストライセンス」](https://www.google.com/url?q=http://communities.bentley.com/products/licensing/w/licensing__wiki/2771&sa=D&usg=AFQjCNFV-T_bwA2Ptwbb8bTuQfBjt0H6-A)と呼ばれています。ライセンス管理は、クラウドまたはオンプレミスで実行され、すべてのライセンスユーザーに無料アクセスを提供します。クライアントは、使用量ごとに便利に支払い、所有コストを負担することはありません。ただし、ライセンスの使用は合意された制限に制限されず、お客様は予期せぬ請求に驚かされる可能性があります。

### DSLS「カジュアルネームドライセンス」

このライセンスフレーバーは、使用量を月あたり40時間のクォータに制限します。「カジュアルライセンス」クォータの超過に対して、DSLSは明示的に警告しません。このクォータを超過した後も、ライセンスは自由に付与されますが、高額な請求が伴います。

## 「オープンチェック」で何ができますか?

最初に行うべきことは、ライセンスの使用状況を監視し、ライセンスの制限が近づいていることを認識することです。

この情報が利用可能になると、対策を講じることができます。

OpenLMは、事前定義されたルールに従ってアプリケーションの起動をインターセプトし、ライセンス管理者が予期せぬライセンス支出に驚かされるのを回避するのに役立つ「OpenLM Applications Manager」などの特定のソリューションを実装しています。

## 知識は金なり

このようなすべてのケースの結論は、お客様の認識と、ライセンスソフトウェアのより良い取引を交渉する際に、ライセンス使用履歴の具体的な証拠を提示できることです。
