PagerDuty は、IT チームや DevOps チームが運用上の問題に迅速に対応できるよう支援するインシデント管理プラットフォームです。アラートを一元化し、オンコールスケジュールを自動化し、インシデントの解決を効率化します。

## はじめに

PagerDuty の監視を開始する前に、次のコンポーネントと権限が揃っていることを確認してください。

- OpenLM コンポーネント: [Broker Hub](/cloud/data-collection/broker-hub) で承認された OpenLM Cloud Broker。
- プラットフォーム固有の要件: ユーザーおよびチームデータに対する読み取り権限を持つ新しい API キーを生成するには、PagerDuty アカウントへの管理者アクセスが必要です。

## データ収集の構成

1. API アクセスを有効にする:

Web アプリで、Integrations → Developer Tools → API Access Keys に移動します。

Create New API Key をクリックします。

後でキーを識別しやすいように Description を入力します。

キーが GET 呼び出しのみを行うようにする場合は、必要に応じて Read-only API Key をオンにします。

Create Key をクリックします。

2. 認証情報を追加する: OpenLM Cloud Broker のダッシュボードで PagerDuty インテグレーションを見つけ、API キーを入力します。

![PagerDuty credential configuration in Cloud Broker](/img/saas-platforms/pagerduty/image28.png)
*Cloud Broker での PagerDuty 認証情報の設定*

## OpenLM Platform で PagerDuty を承認

1. OpenLM Platform にサインインします。
2. メニューから **License Servers** → **Pending Server** を開きます。
3. PagerDuty データソースを選択し、**Approve and Merge** をクリックします。

## 連携の検証

1. OpenLM Platform で **Allocation** を開きます。
2. PagerDuty の利用状況データが表示されることを確認します。

:::note
承認後、データの反映まで最大 3 分かかります。
:::

## レポートの閲覧

- **ユーザーアクティビティの推移** — プラットフォームで活発に活動しているユーザーを把握し、シートの再配分に活用できます。
- **期限切れまたは未使用ライセンス** — 非アクティブなユーザーを特定し、シートを回収します。
