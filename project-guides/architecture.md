The site is built with **Docusaurus 3** (Classic preset), serving two doc sets through per-set content plugins, with custom plugins for reading-time and last-updated metadata, a curated sidebar for the cloud set, and a swizzled theme layer for branding. CI on Azure DevOps deploys the static build via `rsync` over SSH.

For day-to-day commands see [Development Workflow](./development-workflow.md). For author conventions see [`CONTRIBUTING.md`](../CONTRIBUTING.md).

## Documentation sets

Two sets are wired into `docusaurus.config.js`:

| Set | Path | Route | Sidebar | Label |
| --- | --- | --- | --- | --- |
| Cloud (current product) | `docs/cloud/` | `/cloud` | `sidebars-cloud.js` (curated) | OpenLM Platform |
| Legacy (Version 25) | `docs/legacy/` | `/legacy` | `sidebars-default.js` (autogenerated) | Version 25 |

Each set is registered through its own `@docusaurus/plugin-content-docs` instance built by the `create_doc_plugin()` helper at the top of `docusaurus.config.js`. The Classic preset is loaded with `docs: false, blog: false` because docs are wired through these per-set plugins instead.

There is no `docs/onpremise/` directory. Older on-prem material lives under `docs/legacy/`.

## Site configuration

`docusaurus.config.js` centralises:

- **Metadata** — `title`, `tagline`, `url`, `baseUrl: /documentation/`, `favicon`, `image`.
- **Locales** — `en` (default) and `ja`. Translation source-of-truth is `i18n/ja/`.
- **Doc plugins** — one per set, sharing `defaultSettings` (breadcrumbs, last-update, collapsible sidebar, the custom `discontinued` admonition keyword).
- **Custom plugins** — `src/plugins/reading-time` and `src/plugins/last-updated`. Both receive `docsDirectories: docs.map(d => ({path, id}))`, so adding a new doc set means updating these plugin registrations too.
- **Redirects** — `@docusaurus/plugin-client-redirects` defines:
  - hand-written `{ from, to }` entries for moved pages,
  - a `createRedirects(existingPath)` function that generates redirects for whole URL families (e.g. legacy `/cloud/services/*` → `/cloud/*`, `/cloud/data-collection/connect-license-managers/*` ↔ older interfacing-lms paths).
- **Theme** — Mermaid is enabled (`@docusaurus/theme-mermaid`) with a custom palette. Prism uses `github` (light) / `dracula` (dark).
- **Search** — Algolia DocSearch with `askAi` (Grok) enabled and `replaceSearchResultPathname` rewriting `/docs/` → `/`.
- **Navbar & footer** — three left dropdowns (Docs, Product, Changelog), a per-set version dropdown on the right, and a locale dropdown. The footer is content from config but rendered through a swizzled component (see *Theme overrides* below).
- **Announcement bar** — date-gated by `ANNOUNCEMENT_RELEASE_DATE`; visible for 7 days after that date.

## Source customisations (`src/`)

```
src/
  components/   23 reusable React components for MDX (cards, checklists,
                arcade embeds, deprecation banners, hero, etc.)
  theme/        13 swizzled Docusaurus theme components: Admonition,
                BlogLayout, DocCategoryGeneratedIndexPage, DocItem, DocRoot,
                Error, Footer, Layout, Navbar, NavbarItem, Root, SearchBar,
                SearchPage
  plugins/      Custom Docusaurus plugins:
                  reading-time/  computes a reading-time estimate per page
                  last-updated/  injects last-updated timestamps per doc set
  pages/        Standalone routes (homepage, changelog, release-notes,
                supported-software, privacy-policy)
  context/      React context providers used across the theme overrides
  css/          custom.css — global theme variable overrides
  utils/        Small helpers consumed by components and pages
  img/          Images embedded by React components (not by MDX)
  static/       JSON data consumed at runtime (e.g. release notes)
```

The hero on the homepage is a swift.org-style canvas-2D swoop entrance in `src/components/HomepageHero/heroAnimation.js` (animejs timeline, `prefers-reduced-motion` fallback), compositing re-tinted painted artwork from `static/img/homepage/` — see the `NOTICE.md` there for the artwork's Apache-2.0 provenance. Seam swoops between the homepage sections are revealed and parallaxed on scroll by `scrollSwoops.js`.

## Static assets

- `static/` — copied verbatim into the build. Use for shared images (`/img/...`), favicons, JSON consumed by widgets (`static/release-notes/broker.json` and the matching `*-ja.json` for Japanese), `.drawio` source files for diagrams.
- Page-local images can also live next to the MDX file and be referenced relatively.

## Build pipeline

1. Authors edit `.md` / `.mdx` files in `docs/`, optionally importing components from `src/components/`.
2. For Japanese: `npm run write-translations -- --locale ja` extracts strings into `i18n/ja/`; translators edit the copies in place.
3. Local preview: `npm run start` (or `--locale ja`).
4. Production build: `npm run build` produces `build/`. Local smoke test with `npm run serve`.
5. CI (`azure-pipelines.yml`, triggered on `master`):
   1. Install AWS CLI and download the deploy PEM (Azure secure file).
   2. Run `scripts/check-a11y-source.py` and `scripts/check-a11y-contrast.py`.
   3. `npm install --force && npm run build`.
   4. Run `axe-core` against a small set of routes (homepage, getting-started, privacy-policy, accessibility) for WCAG 2.1 AA. Findings warn but don't fail the build.
   5. Open SSH ingress on the AWS security group for the runner's IP, `rsync` `build/` to `docs_deploy@openlm.com:/var/www/www/openlm.com/documentation/`, then revoke the SG entry.
6. The `Dockerfile` provides a `dev` stage (hot-reload server on `:3000`) and `prod`/`serve` stages (immutable `npm ci` + `npm run build`/`serve`) for containerised work.

## Quality tooling

- **Vale** — `npm run vale` runs prose linting against `docs/`. Configuration in `.vale.ini`.
- **Accessibility** — Python source/contrast checks plus `axe-core` in CI. Both currently warn rather than block; new violations should still be fixed.
- **Type-check** — `// @ts-check` JSDoc annotations in `docusaurus.config.js` and `sidebars-cloud.js` give the editor type information without a TypeScript build step.

## Auxiliary scripts

- `generate-analysis.js` (root) — one-off Node script that exports doc content into branded Word `.docx` reports using the `docx` library. Not part of the build.
- `scripts/check-a11y-source.py` / `check-a11y-contrast.py` — accessibility validators run by CI.
- `scripts/populate_saas_platform_docs.py` — generator for the SaaS-platform pages under `docs/cloud/data-collection/connect-license-managers/saas-platforms/`.
